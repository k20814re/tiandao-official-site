# B 方案｜第一批展覽人工查核作業

目的：先讓現有 /b2b/explore/ 顯示「已經有可靠證據、並經授權發布」的台灣展覽。沒有完成查核的候選資料不得顯示。

## 來源及欄位（每場必填）
- title_zh：活動官方名稱，不自行改名
- starts_at / ends_at：官方活動頁確認的展期（台灣時區）
- city / venue_name：官方活動頁的縣市與場館
- official_url：直接指向該場活動的 HTTPS 頁面；首頁、展館總表與主辦單位首頁不能當作單場證據
- source_checked_at：查核時間與時區
- facts_verified：人工逐欄比對後才可勾選
- source_license_cleared：依實際來源使用條款或取得授權後才可勾選；公開可見不代表可重製
- publication_status：匯入前一律 draft；不能用 CSV 直接上架
- reviewer_notes：查核者、來源證據、差異、待補欄位；不要儲存個資或密鑰

## 上線前必要流程
1. 收集官方活動頁連結；以原始來源核對活動名稱、日期、地點、狀態。
2. 將來源授權與自有文字、圖片分開檢查；不使用未授權海報或圖片。
3. 每筆經人工核實後先儲存為草稿，未通過者保留原因。
4. 在**隔離 staging** 執行 SQL 權限稽核與測試，確保不會繞過發布管控。
5. 由已驗證的安全發布程序或明確批准的受控部署流程發布已核實資料；不得在瀏覽器直接改 publication_status=published。
6. 檢查手機與桌面版的縣市、日期、類別篩選，以及空結果、過期活動、活動官方連結。
7. 經使用者批准後才合併到 main、部署正式站或更改現有 Supabase。

## 第一版驗收
- 首頁能查詢 Supabase 已發布且未刪除的展覽。
- 不把 40 筆未核實候選資料或前端寫死資料當成已發布。
- 每場有可追溯的官方活動證據及查核時間。
- 來源失敗時顯示錯誤，不回退到未核實清單。
- 平台只提供資訊，不代訂、不收款。
